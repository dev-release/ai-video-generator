# Spec: pipeline (граф, стан, гроші, помилки)

> Спільні правила для всіх вузлів. Специфікація етапу може їх звужувати, але не послаблювати.

## Порядок вузлів

```
script → voice → voice_check ─(WER>0, ≤ MAX_VOICE_ATTEMPTS)→ voice      ← брак голосу ловимо ДО відео
                      │ ok (+ вікно мови, паузи)
         approve_script[HITL, опційно: сценарій + промпти відео] ─(переписати)→ script
                      │ апрув (хеш плану)
         video: шот 1 з тексту ─(ще є шоти)→ keyframe(кадр стику шота k−1, $0)
           ↑                                   → approve[HITL, опційно: кінець шота k−1 + кадр]
           └──────── шот k з кадру стику ←───────┘
                │ усі шоти
                → lipsync(губи під НАШ звук; нема обличчя → пропуск) → assemble(наш звук)
                → verify ─(WER>0)→ END (стоп з diff; платне не перегенеровується автоматично)
                    │ ok
                sync_check (рот vs наш звук; SYNC_GATE warn|block) → END
```

- **Без окремої картинки** (рішення власника 2026-10-01): шот 1 — text-to-video, шот k —
  image-to-video з кадру стику шота k−1 (spec keyframe.md, video.md). Шоти — послідовно, до
  `schema.MAX_SHOTS` = 10 (запит власника 2026-10-01); кожен наступний — за тим самим правилом.

- **voice перед video**: тривалість шота — з довжини wav; голос коштує центи, відео — долари.
- **verify на фінальному файлі** (CONTEXT §13): ловить і помилки зведення.
- **Фінальні ворота без петлі**: голос уже пройшов `voice_check`; новий голос тягнув би нове
  відео й lipsync (аудит бюджету 2026-09-30). Перегенерування — лише явне (UI / `--regen`).

## Вхід

Один текст (CONTEXT Z1): репліка в лапках усередині ідеї або `--line`. CLI
(`python -m pipeline "…"`) і веб-UI (`POST /api/runs`) валідують тією самою моделлю `Brief`.
**CLI автоматичний** (PDF: «одна команда / один виклик — на виході відеофайл»); апрув людиною —
`--review` або UI.

## Стан

`PipelineState` (`schema.py`): `run_id`, `brief`, `run_dir`, по полю-результату на вузол,
лічильники воріт. Вузол — чиста функція `(state) -> patch`. Чекпоїнт — SQLite (LangGraph).
Пам'ять прогону на диску (`runmemo.py`): `takes.json` (дублі, «свіже»), `approvals.json` (апрув
людини за хешем кадру) — переживає перезапуск графа з чистим станом.

## Артефакти

Все під `runs/<run_id>/`. Кожен артефакт — з `.input_hash` (ідемпотентність: той самий вхід →
провайдер не викликається). Запис **атомарний** (`media.atomic`: `.tmp/` → `os.replace`) — читач
бачить або старий повний файл, або новий повний. URL медіа в API — з версією (`?v=mtime`).

## Платні виклики — одне правило для всіх (CLAUDE.md №4, №9)

Будь-який платний артефакт — через `nodes.produce()`:
1. свіжий у прогоні → нічого;
2. є у **спільному кеші** (`Settings.cache_root()`, за ключем входу) → копія, $0. Ключ включає
   дубль (take) і «свіже» (salt), тож явне перегенерування й `--fresh` кеш обходять. Спільний кеш —
   **лише для платних моделей** (`price.usd > 0`): його мета — не платити двічі. Безкоштовні
   (локальні, fake) генеруються заново, інакше зміна нашого коду адаптера не видна в прогонах і
   евалах (AI_LOG 2026-10-01: евал міряв звук, згенерований старим адаптером Kokoro);
3. інакше `tracer.spend(node, provider, estimate, key=…)`:
   - `provider.ready()` (ключ/клієнт) **до** резерву — без фантомних витрат;
   - резерв зі стелями (ліміт викликів етапу → стеля прогону → стеля доби з `_ledger.jsonl`);
     та сама робота, вже зарезервована й не завершена (падіння, задача ще йде) — без нового резерву;
   - помилка: провайдер **точно не списав** (`billing.not_billed`: 4xx на відправці, нема ключа,
     запит не дійшов) → резерв повертається; інакше лишається (сумнів — на користь стелі);
   - успіх: фактична ціна, якщо провайдер її знає (Claude — з usage).

**Ретраї** (`retry.py`): платна відправка — лише 5xx і «запит не дійшов»; таймаут після
відправки — ніколи (провайдер міг виконати). Ідемпотентні читання — ще й таймаути. 4xx/429 — ні.
**Асинхронні задачі fal** (відео, lipsync): задача пишеться в `<out>.fal-job.json` одразу після
відправки, результат — у `<out>.fal-result.json` до завантаження файлу; опитування з власними
ретраями; дедлайн → `FalStillRunning` (не ретрай) → продовження підхоплює ту саму задачу.
**Ліміти наступних моделей** (`input_s` у реєстрі) перевіряються **до** платного кроку, що
створює їхній вхід (preflight і вузол video), а не після оплаченого відео.

## Вартість і обмежувачі

Ціни — `pricing.cost(spec, calls=, seconds=, chars=)` із `models.yaml`; платна модель без ціни з
джерелом не завантажиться. Стелі: `MAX_RUN_COST_USD` (дефолт $1, ≤ 5), `MAX_DAILY_COST_USD`
(дефолт $3, ≤ 20), `MAX_CALLS_PER_UNIT` — платних викликів на одиницю (дубль сценарію, артефакт
шота): ловить зациклення й не залежить від кількості шотів. `preflight.py` до старту: ffmpeg, ключі (лише назви),
`voices.yaml`, ліміти моделей, очікувана й найгірша вартість проти стелей → відмова до витрат.

## Трейс

`trace.jsonl`: `{ts, node, event, cum_cost_usd, …}`; події витрат — `charge`, `refund`, `settle`,
`spent`, `failed_billed`, `pending`, `resume_paid`, `reused`. Поточна вартість — останній запис.
У консолі — етап і накопичена вартість. `print` заборонено.

## HITL

Дві зупинки, обидві — до оплати відео:
1. **Сценарій і промпти відео** (spec approve_script.md): після воріт аудіо, до першого відео —
   дослівно ті промпти, що підуть у модель; «переписати» — новий дубль сценарію.
2. **Між шотами** (spec keyframe.md): після шота 1, до оплати шота 2 — кінець відео шота 1 поруч
із кадром стику; LangGraph `interrupt()` у вузлі `approve`, у паузі — ціна того, що запустить апрув
(`next_cost_usd`). Апрув прив'язаний до хешу кадру: той самий кадр вдруге не питаємо, новий без
людини не проходить. Один шот — паузи нема. Вмикається `--review` /
UI; CLI за замовчуванням автоматичний. Між голосом і зведенням HITL свідомо нема — там код.

## Часткове перегенерування

Новий **дубль** артефакту шота (`runmemo.bump_take`): UI «перегенерувати», CLI
`--run-id … --regen voice:s1`. Дубль змінює ключ і seed (крок `TAKE_STRIDE`) — справді нове;
решта етапів — з кешу. «Продовжити» (UI / `--run-id`) — з місця зупинки, оплачене не повторюється.

## Відкриті питання
- 429 не ретраїться (CLAUDE.md №4). Упремося в ліміти — рішення власника про `Retry-After`.
- Падіння процесу між відправкою задачі fal і записом `fal-job.json` (мілісекунди) — задача
  загубиться; повна гарантія — ідемпотентні ключі на боці провайдера (fal їх не документує).
