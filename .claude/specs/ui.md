# Spec: ui (веб-оболонка)

## Призначення
Людина вводить ідею й до 10 реплік, бачить граф етапів наживо, вартість, апрувить сценарій із промптами відео й кадри, слухає голос,
дивиться фінал і звірку WER, перегенеровує окремий артефакт. Це **оболонка** над `graph.Runner` —
та сама логіка, що в CLI; UI нічого не вирішує.

## Вхід
`StartRequest(Brief)`: `idea`, `lines[1..10]`, `mode: fake|real`, `auto_approve`. Правила реплік —
успадковані від `Brief` (FastAPI → 422 з полем). Ліміти для підказок у формі — з `GET /api/limits`.
Форма за замовчуванням шле `auto_approve=true`: як CLI, один запуск → відео з озвучкою без зупинок
(PDF, Частина 4). Галочка «review before video» — HITL за бажанням (spec approve_script.md,
keyframe.md). До запуску форма показує моделі
обраного режиму (`Limits.models_by_mode`) — видно, яким голосом прозвучить репліка.
Примітки обраних моделей (`Limits.notes_by_mode`, поле `note` запису в `models.yaml`) видно під
списком моделей — напр. що fake-голос `tone` не вимовляє слів і як увімкнути Kokoro.

## Вихід (контракт API = pydantic-моделі в `api.py`)
| Метод | Відповідь |
|---|---|
| `GET /api/limits` | `Limits` |
| `POST /api/preflight` | звіт preflight: problems, warnings, estimate/worst, стелі |
| `POST /api/runs` | 202 `{run_id}`; 409 `{problems}` якщо preflight не пройдено; 422 — невалідний вхід; `fresh` — без спільного кешу |
| `GET /api/runs` | `RunSummary[]` з тек `runs/` (включно зі скопійованими з іншої машини) |
| `GET /api/runs/{id}` | `RunView`: статус, вузли (pending/running/done/error/waiting, час, $, к-сть запусків), артефакти з URL, `AsrCheck`, `interrupt` |
| `GET /api/runs/{id}/events` | SSE: рядки `trace.jsonl` наживо |
| `POST /api/runs/{id}/approve` | resume після `interrupt()` з `{shot_id: approve\|regenerate}` |
| `POST /api/runs/{id}/regenerate` | новий дубль артефакту `voice\|video\|lipsync` шота (take: новий ключ і seed); решта з кешу; новий кадр — знову апрув |
| `POST /api/runs/{id}/resume` | продовжити з місця зупинки: оплачене не повторюється, задачі fal підхоплюються |
| `POST /api/runs/{id}/rewrite` | новий дубль сценарію (ті самі репліки, нова постановка й промпти відео) і прогін знову; зупинки — як у самого прогону (`ui.json.auto_approve`) |
| `/media/**` | файли прогонів |

Типи TS генеруються з OpenAPI (`make ui-types` → `ui/src/api-schema.ts`); pre-commit падає, якщо
OpenAPI змінився, а `ui/openapi.json` — ні.

## Інваріанти
- Стан прогону будується з артефактів + `trace.jsonl` + чекпоїнта; UI не тримає власного стану
  пайплайну (окрім «у черзі/йде» в пам'яті процесу).
- Один прогін за раз (`ThreadPoolExecutor(max_workers=1)`): паралельні запуски множать витрати.
- Real-режим проходить preflight до старту: без ключів/каталогу голосів → 409, $0.
- Real у формі — лише після показу ціни: «Показати ціну» → «Підтвердити запуск за ~$X».
- Пауза апруву показує ціну наступного кроку (`interrupt.next_cost_usd`); хибне рішення — та сама
  пауза з `interrupt.error`; ключі рішення не для поточної паузи — 422 (spec pipeline.md, HITL).
- Апрув сценарію (`interrupt.kind = approve_script`, галочка «review before video» / `--review`) —
  до будь-якого відео: персонажі, і для кожного шота — репліка, старт (з тексту / з кадру стику),
  тривалості й **дослівний промпт** моделі відео, negative prompt; «✓ Approve script» / «↻ Rewrite
  script» (spec approve_script.md).
- Пауза апруву кадру (`approve_cut_frames`, лише 2+ шоти того самого мовця) — між шотами: для кожного кадру стику UI показує
  **кінець відео попереднього шота** (плеєр на `at_s`) поруч із вирізаним кадром; «↻ Інший» — новий
  дубль відео попереднього шота (кадр з нього похідний). Новий кадр — знову апрув; голос — ні.
- Перегенерування: `voice|video|lipsync` шота; кадр стику окремо не перегенеровується (він — кадр
  відео попереднього шота).
- Відмова фільтра контенту моделі (`RunView.rejected = {node, shot_id}`, spec video.md): замість
  «Resume» (повторив би той самий промпт) — пояснення і дві дії: «✎ Rewrite script» і «↻ New take
  of sN». Помилка попередньої спроби зникає, щойно прогін стартує знову.
- Будь-яка помилка → «↻ Run again from the start» (запит власника 2026-10-02): форма `#/new?from=<id>`
  з тим самим текстом, режимом і review (`RunView.auto_approve`); ціну людина бачить і підтверджує
  у формі, як за будь-якого старту; готові платні артефакти — зі спільного кешу.
- Шлях `run_id` не виходить за `runs/` (404 на traversal).
- Готове відео з озвучкою — над графом; нове (кінець прогону, новий дубль) прокручується в поле
  зору, навіть якщо людина прокрутила вниз до апруву.
- Перевірка будь-якого етапу (звук, кадр) — прогін того самого графа; окремих сторінок чи
  ендпоінтів для одного етапу нема (AI_LOG 2026-09-30).
- Значення ключів ніде не віддаються.
- Артефакти — по шотах: голос — один на шот (`voice/<shot>.wav`; технічні `.shot`/`.lip` не
  шоти); кліп — `stage: video` (від моделі відео, етап «Відео») і `stage: lipsync` (з губами під наш
  звук, етап «Lipsync»). Кнопка перегенерування отримує лише справжній id шота.

## Детерміноване vs модель
UI — нуль рішень. Валідація, ліміти, вартість, статуси — з Python.

## Перевірка
`tests/test_api.py` (TestClient + fake): ліміти, 422, 409 без ключів, повний потік з апрувом,
регенерація голосу не чіпає кадри, 404/traversal, прогін без чекпоїнта. Фронт: `tsc` strict +
`oxlint --deny-warnings` + `vite build`. Браузер (`tests/test_browser.py`, Chrome): один запуск →
відео з озвучкою без зупинок і видно без прокрутки; з «review before video» — апрув сценарію з
промптами у полі зору, далі пауза кадру, апрув, фінал у полі зору. Шоти s1…s10 — у порядку шотів. Ручна перевірка: `make ui`.

## Вартість і час
$0 сам по собі. Прогін — як у CLI.

## Помилки
Помилка вузла → `status=error`, `error` з трейсу, вузол червоний на графі. Бекенд недоступний →
банер у сайдбарі, без мовчазного `catch`.

## Відкриті питання
- Авторизації нема: UI розрахований на localhost. Для спільного доступу — окреме рішення.
