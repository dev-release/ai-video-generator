# Spec: script

## Призначення
Ідея + репліки юзера → структурований сценарій на 1–`MAX_SHOTS` (10) шотів. Репліки пише **юзер**; модель
придумує лише персонажа, емоцію й кадри. Модель фізично не може перефразувати репліку: поля
`line` у її схемі нема, код вставляє репліки сам.

## Вхід
Один текст ідеї (1–3 речення), як у завданні: «закинути ідею… репліка — як прописана в тексті на
вході». Репліки — фрагменти в лапках (`"…"`, `“…”`, `«…»`), код вирізає їх **дослівно** (вміст
між лапками, без змін). Явна форма — `--line` / поле `lines` (тоді лапки в ідеї не розбираються).
Нема ні лапок, ні `lines` → `ValidationError` з прикладом; модель репліку не пише ніколи.
Приклад: `A girl finds a letter and whispers: "This handwriting is mine."`

`Brief` (CLI, API, UI — однаково, валідатор `mode="before"`):
```python
class Brief:  idea: str (3–500 символів)
              lines: list[str] (1–MAX_SHOTS=10)  # кожна — окремий шот, порядок = порядок у ролику
```
Валідація реплік — **до** виклику моделі (дешево й зрозуміло юзеру): без `[ ] ( ) * < > { }`,
без пробілів по краях, 3–45 слів на репліку, ≤ 60 сумарно (≈ 2.5 сл/с → ≤ 24 с мови).

## Вихід моделі
`ScriptDraft` (JSON-схема structured output):
```python
class DraftShot:   character_id, delivery: Delivery, visual_prompt, camera   # БЕЗ line
class ScriptDraft: title, style, characters: list[Character] (1–MAX_CHARACTERS=4), shots: list[DraftShot]
```
`len(draft.shots) == len(brief.lines)` — інакше невалідний вихід (цикл виправлення).

## Вихід вузла
`Script` → `runs/<id>/script.json`; `Shot` = `DraftShot` + `line = brief.lines[i]` + `id = s{i+1}`.
Також `runs/<id>/brief.json`.

## Інваріанти
- `Shot.line` байт-у-байт == `brief.lines[i]`. Після вузла не змінюється ніде (CLAUDE.md №1).
  Тест: `script.json` ↔ `brief.json` ↔ кінець тексту TTS-запиту ↔ еталон verify.
- `Delivery` — enum (див. `voice.md`); `VoiceProfile` — enum. Модель не вигадує значень.
- **Стать персонажа — поле моделі, відповідність голосу — перевірка коду** (власник 2026-10-01: «в
  останньому тесті жінка-персонаж, а голос чоловічий»). `Character.gender: female | male` — як
  персонаж виглядає в кадрі; `voice_profile` тієї ж статі (профілі `female_*` / `male_*`, стать
  профілю — у `schema.profile_gender`); `look` прямо називає стать («young woman», «old man»),
  і для фентезі/тварин теж — бо з `look` малює відео-модель. Невідповідність → `ValidationError` →
  цикл виправлення з поясненням для моделі. Нейтрального профілю нема: персонаж у кадрі говорить
  голосом, що збігається з обличчям.
- **Кілька персонажів** (власник 2026-10-01): кожна людина, що говорить, — окремий `Character`
  (1–`MAX_CHARACTERS`=4) зі своїм `look`; кожну репліку отримує той, хто її каже (за ідеєю: «він
  питає — вона відповідає»; діалог без підказок чергує мовців). `look` різних персонажів різні
  (інакше відео намалює одну людину) — перевірка коду → цикл виправлення. Голоси розводить код
  (spec voice.md); модель обирає лише профіль, що пасує персонажу.
- Кожен `character_id` існує в `characters`.
- Мова — англійська (ринок My Drama, ASR точніший).
- **Кадр для мовлення** (промпт `prompts/script.md`, версія `PROMPT_VERSION`): **рот мовця видно** —
  анфас, ¾ або погляд убік на співрозмовника за кадром, можна йти й говорити, розповідати комусь
  (власник 2026-10-01: «не обов'язково дивитись у камеру»); не можна — повний профіль, спиною,
  обличчя в тіні; рот нічим не закритий (руки, папір, чашка); у кадрі говорить лише мовець. Причина — lipsync і вимір губ працюють лише на
  видимому обличчі (spec sync.md: обличчя, нахилене вниз, не виміряти). Шот 2 того самого
  персонажа продовжує той самий момент і місце (він генерується з кадру стику — spec keyframe.md):
  дія/реакція й рух камери, не нова локація. Різні персонажі — те саме місце й стиль.

## Детерміноване vs модель
Модель: персонаж (зовнішність, голосовий профіль), емоція шота, опис кадру, стиль.
Код: репліки, їх валідація, id шотів, ліміти, тривалості (з'являються з wav у voice).

## Перевірка
Тести на fake: репліка з `[` → `ValidationError` без виклику моделі; 11 реплік → помилка;
`script.json` містить репліки байт-у-байт; draft з іншою кількістю шотів → цикл виправлення;
ідемпотентність (другий прогін не кличе writer).

## Вартість і час
Claude, ~1.5k in / ~0.4k out токенів → центи, 5–15 с. Model id і ціна — звірити через скіл
`claude-api` перед підключенням.

## Помилки
- Невалідний вихід (pydantic) → до `MAX_SCRIPT_FIX_ATTEMPTS` повторів із текстом помилки в
  промпті; далі стоп. Це не мережевий ретрай, а виправлення.
- 5xx/таймаут → загальне правило (pipeline.md). 4xx → стоп.
- Ідемпотентність: ключ = hash(idea + lines + model + PROMPT_VERSION + дубль). Дубль зсуває «переписати»
  в апруві сценарію (spec approve_script.md) — новий платний виклик, ліміт `MAX_CALLS_PER_UNIT` на дубль.
