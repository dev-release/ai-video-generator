# ui-dev — оболонка без власної логіки

Джерела правди: spec `.claude/specs/ui.md`; UI і CLI — дві оболонки над одним `graph.Runner`.

## Правила

1. **Логіка — у Python.** Ліміти, валідація, вартість, статуси, моделі режиму — з API. Фронту
   потрібне нове правило → спершу поле в `Limits`/`RunView`, потім UI. Підказки у формі лише
   дублюють бекенд для швидкого фідбеку; вирішує 422.
2. **Нових сторінок чи ендпоінтів для одного етапу не робити** без прямої вимоги власника:
   перевірка етапу — прогін графа, результат — відео (CLAUDE.md, «Як працювати з власником»).
3. **Контракт = pydantic-моделі відповідей** в `api.py`. Після зміни `api.py` чи `schema.py` —
   `make ui-types`; типи TS — лише з `ui/src/api-schema.ts`, руками — тільки звуження JSON-полів.
4. **Без мовчазних `catch`** — помилка видна людині (банер/картка), CLAUDE.md №4.
5. **React:** похідний стан рахувати в рендері; ефекти — лише для зовнішніх систем (SSE,
   інтервали, прокрутка DOM); хуки — до ранніх `return`.
6. **Головне — на екрані:** те, заради чого людина прийшла (готове відео), видно без прокрутки.
7. **Стиль:** CSS-змінні в `ui/src/index.css`, світла й темна тема; без UI-кітів.

## Команди

```bash
make ui          # бекенд :8000 (--reload) + Vite :5173; спершу перевір, чи порти вільні
make ui-types    # типи TS з OpenAPI
make ui-check    # npm ci + tsc strict + oxlint + vite build
uv run pytest -q tests/test_api.py tests/test_browser.py
```

## Перевірка

Змінилось видиме → тест у `tests/test_browser.py` саме на це (видимість — `to_be_in_viewport`, не
лише наявність). Далі скіл `wrap-up` — там і сценарій власника на живому UI.
