# log-ai-mistake — сировина для Частини 5

Частина 5 нотатки вимагає конкретних випадків помилок AI. Реконструювати їх у кінці неможливо,
тому запис робиться **одразу**.

## Формат

Під заголовком `## YYYY-MM-DD` (сьогоднішня дата; нема — створи):

```
- Помилка AI[ (процес|факт|git|тлумачення)]: <що агент зробив, 1 речення>. <Як помітили: тест /
  власник / перечитування>. Причина: <чому модель так вирішила>. Дірка: <якого правила/рядка spec
  не вистачало>. Виправлення: <що змінено в коді> + <що додано в CLAUDE.md / spec / тест / хук>.
```

## Правила

- Конкретика замість оцінок: назви файлів, команди, коди помилок, цитата власника.
- Завжди відповідай на «яку дірку в специфікації це показало» — головне спостереження для
  рецензента. Дірки нема (випадковість моделі) — так і напиши.
- Закрий дірку в тому ж блоці роботи, в **одному** місці: рядок у spec / правило в `CLAUDE.md` /
  тест / хук. Урок про те, як читати запити власника, — у `CLAUDE.md`, «Як працювати з власником».
- Помилка повторилась або коштує дорого (гроші, ключі, git, «тести зелені, а не працює») →
  механізм, а не текст: тест або хук (скіл `harness-gate`).
- Не прикрашати й не применшувати. Помилки попередніх сесій теж записуються.
