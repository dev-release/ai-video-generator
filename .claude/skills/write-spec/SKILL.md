# write-spec — специфікація як контракт для агента

Spec — те, проти чого агент пише код і проти чого тест доводить поведінку. Кожна AI-помилка в
`AI_LOG.md` майже завжди = відсутній рядок тут.

## Кроки

1. **Звірка з задачею.** Spec не суперечить CONTEXT («Рішення власника»; §3 — репліка звучить
   дослівно у відео; §13) і PDF, Ч.4. Суперечить → питання власнику, а не spec.
2. Структура — `.claude/specs/_TEMPLATE.md` (розділи не прибирати; порожній → «—»).
3. `.claude/specs/pipeline.md` — спільні правила; spec етапу може їх **звужувати**, не послаблювати,
   і не переписує, а посилається на них.
4. **Вхід/Вихід** — реальні pydantic-моделі з `src/pipeline/schema.py` і шлях артефакту під
   `runs/<run_id>/`. Нової моделі нема → поля в spec, потім `schema.py`.
5. **Інваріанти** — лише перевірювані твердження («WER == 0», «тривалість 8–30 с»), кожен має тест
   у розділі «Перевірка». Невимірне («якісно») — у «Відкриті питання».
6. **Детерміноване vs модель** — явно, що вирішує код (CLAUDE.md №5). Модель вирішує число →
   переписати.
7. **Помилки й гроші** — за CLAUDE.md №4 і №9: що платне; що ретраїться (платна відправка vs
   читання); ключ ідемпотентності (що саме хешується); що робити при збої після оплати.
8. **Зовнішні API** — кожне твердження про параметр чи поведінку провайдера має посилання на
   офіційну доку. З пам'яті моделі не писати (AI_LOG 2026-09-29: вигадане поле `voice_settings`).
9. **Вартість** — ціна живе в записі моделі в `src/pipeline/models.yaml` (`source` + `checked`);
   у spec — порядок цифри з посиланням на запис.
10. **Узгодь сусідів.** Те саме описано в іншій spec, скілі чи README? Лишити одне місце, в інших —
    посилання. `tests/test_docs.py` ловить застарілі імена, але не застарілий зміст.
11. Spec виправлялась через розбіжність або помилку AI → `AI_LOG.md` (скіл `log-ai-mistake`),
    у тексті: «дірка в spec: …».

Кінець — скіл `wrap-up`.
