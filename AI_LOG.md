- Помилка AI: у першій версії pre-commit агент написав `grep -q … | grep -v example && fail` —
  `grep -q` нічого не виводить, тож другий grep завжди отримував порожній вхід і перевірка була
  мертвою. Помітив при перечитуванні, прибрав. Урок: хуки-ворота теж потребують тесту
  (синтетичний staged `.env` → коміт має впасти).
- Помилка AI, знайдена лише завдяки тесту воріт: сканер секретів у pre-commit **ніколи не
  спрацьовував**. Причина — `set -o pipefail` + `grep -q`: `grep -q` виходить на першому збігу,
  лівий бік пайпу отримує SIGPIPE, pipefail робить увесь `if` хибним → «збіг знайдено» читалось як
  «не знайдено». Друга дірка: патерни ключів збігались із текстом самого хука. Виправлення:
  `>/dev/null` замість `-q`, хук виключено зі сканування. Перевірено: фейковий `sk-ant-…` у staged →
  exit 1, чисте дерево → exit 0. Урок для spec/нотатки: ворота без негативного тесту — декорація.
- Помилка AI (процес, не код): попри `bypassPermissions` агент ганяв `cd <repo> && …` — складені
  команди з `cd` усе одно дають запит на дозвіл, власник отримав промпти, яких просив уникнути.
  Плюс закінчував відповідь «можу почати?» замість дії. Виправлення: абсолютні шляхи / `git -C` /
  `make -C`, правило записано в пам'ять агента. `git reset --hard` перенесено з `ask` у `deny` —
  без промпта, але й без ризику стерти незакомічену роботу.
